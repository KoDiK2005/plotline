# Plotline

Plotline — конструктор и плеер ветвящихся интерактивных историй. Сочиняйте сюжет как граф сцен и выборов, проверяйте его на ошибки одним кликом и проходите получившуюся историю тут же, в браузере.

## Возможности

- **Визуальный редактор графа** — сцены и переходы между ними редактируются как узлы и связи на холсте ([React Flow](https://reactflow.dev/)): перетаскивание, авторасстановка по слоям, мини-карта, кнопка «★ К старту» для мгновенного перехода к стартовой сцене на любом по размеру графе; недостижимые из старта сцены сразу помечены на холсте значком «⚠ Недостижима», а сцены без рабочих исходящих переходов (концовки) — значком «🏁 Концовка».
- **Undo/redo** — любое изменение истории (узлы, связи, текст, переменные) можно отменить и повторить кнопками в редакторе или Ctrl+Z / Ctrl+Shift+Z; быстрые правки одного поля группируются в один шаг отмены.
- **Описание истории** — короткий текст, который виден на карточке истории в библиотеке, редактируется прямо в редакторе через панель «Описание».
- **Инспектор сцены** — заголовок, текст, варианты выбора и их цели редактируются в боковой панели; одной кнопкой сцена назначается стартовой, другой — дублируется целиком (с вариантами и их связями) для быстрого создания похожей сцены; у связанного варианта есть кнопка перехода прямо к целевой сцене, а порядок вариантов можно менять стрелками ▲/▼ — именно в этом порядке они показываются игроку.
- **Проверка целостности истории** — встроенный валидатор находит недостижимые сцены, пустой текст, выборы без цели, отсутствие старта, отсутствие хотя бы одной достижимой из старта концовки (значит история может закончиться бесконечным циклом), переменные, которые ни на что не влияют, переменные, которые читаются в условиях, но никогда не меняются эффектами (а значит ветка всегда в одном состоянии), и переменные с одинаковыми именами (их легко перепутать в списках условий и эффектов), с переходом прямо к проблемной сцене.
- **Поиск и замена по всей истории** — панель «Найти и заменить» в редакторе ищет подстроку в названиях сцен, тексте сцен и тексте вариантов выбора одновременно, показывает список совпадений с переходом к нужной сцене и заменяет все совпадения один кликом одним шагом отмены.
- **Превью сцены прямо из редактора** — кнопка «▶ Превью» в инспекторе сцены открывает мини-плеер, который запускает прохождение с этой сцены без изменения стартовой и без сохранения каких-либо изменений в историю — удобно проверить любую ветку, не выходя из редактора; варианты в превью пронумерованы и тоже выбираются клавишами `1`–`9`.
- **Плеер с двумя режимами** — обычное текстовое прохождение со списком вариантов и историей пройденного пути, либо режим карты, где видно всю историю и текущее положение в ней. В текстовом режиме варианты можно выбирать клавишами `1`–`9` — каждый вариант пронумерован.
- **Прогресс и статистика** — для каждой истории отдельно отслеживаются посещённые сцены, найденные концовки и число прохождений (сохраняется в localStorage); кнопка «Сбросить прогресс» на карточке истории в библиотеке (появляется после первого прохождения) обнуляет всё это с подтверждением.
- **Продолжение с места остановки** — если выйти из плеера на середине истории (например, кнопкой «← Библиотека»), при следующем открытии той же истории прохождение возобновляется с той самой сцены и с теми же значениями переменных, а не с начала; об этом сообщает короткая плашка «Продолжаем с места, где вы остановились в прошлый раз». Кнопки «Начать заново» и достижение концовки сбрасывают сохранённую точку — следующее открытие начинается с начала.
- **Отметка уже пройденных вариантов** — при повторном прохождении истории варианты выбора, которые игрок уже брал раньше (в этом или прошлых прохождениях), помечаются галочкой ✓ — удобно для тех, кто хочет исследовать все ветки истории и не запутаться, что уже видел.
- **Оценка времени чтения** — карточка истории показывает примерное время на чтение всех достижимых сцен (из расчёта 200 слов в минуту).
- **Достижения** — сквозные ачивки по всей библиотеке (первая концовка, все концовки одной истории, все концовки везде, своя история, история на 10+ сцен, 10 прохождений, 20 посещённых сцен), открываются по кнопке в шапке библиотеки; для ачивок с накопительным условием (концовки, сцены, прохождения, посещения) под описанием показывается прогресс-бар и счётчик «текущее/нужное», пока ачивка не открыта.
- **Библиотека историй** — поиск (учитывает и название, и описание), сортировка (по дате изменения, по названию, по дате создания), фильтр по состоянию прохождения (все / не начатые / в процессе / все концовки найдены), дублирование, удаление, экспорт в JSON (один файл или резервная копия всей библиотеки) и импорт обратно с валидацией структуры.
- **Шаблоны при создании истории** — диалог «Новая история» даёт выбор: пустой лист, готовая заготовка «Детектив» (завязка → две ветки расследования → общая разгадка) или «Квест» (зов → подготовка → испытание → две альтернативные концовки) — быстрый старт со связанными сценами вместо одного пустого узла.
- **Экспорт в самостоятельный HTML** — любую историю можно скачать как один HTML-файл с инлайн-плеером на чистом JS: без Plotline, без сервера, без зависимостей — открывается прямо в браузере, поддерживает переменные/условия/эффекты, а варианты выбора пронумерованы и выбираются клавишами `1`–`9`, как и во встроенном плеере.
- **Переменные и условные выборы** — у истории можно завести числовые переменные, повесить на любой выбор условие видимости (сравнение переменной с числом: =, ≠, >, ≥, <, ≤) и эффект, который меняет переменную при выборе (присвоить или добавить). Так из ветвящегося рассказа получается полноценная интерактивная фантастика с состоянием: доверие персонажей, найденные предметы, скрытые концовки.
- **Переменные типа «Да/Нет»** — любую переменную можно пометить как булеву (флаг вроде «есть ключ» или «встретил капитана»): начальное значение задаётся выбором Да/Нет вместо числа, а условия и эффекты на выборах для такой переменной показывают простой переключатель Да/Нет вместо полного набора сравнений и операций — старые числовые переменные и сохранённые истории не меняются.
- **Подтверждение удаления переменной** — если переменную ещё используют условия или эффекты хотя бы одного варианта, удаление сначала спрашивает подтверждение и предупреждает, сколько мест в истории потеряют это условие или эффект; неиспользуемая переменная удаляется сразу, без лишнего диалога.
- **Светлая/тёмная тема** на выбор.
- **Доступность модальных окон** — диалоги (подтверждение удаления, новая история, достижения, горячие клавиши) переводят фокус внутрь себя при открытии, возвращают его на исходный элемент при закрытии и закрываются по Escape; иконки-кнопки и поля инспектора сцены/переменных снабжены `aria-label`.
- **Справка по горячим клавишам** — клавиша `?` (или кнопка ⌨ в шапке библиотеки) открывает оверлей со списком сочетаний клавиш во всём приложении.
- Три полноценные сэмпл-истории на русском, чтобы сразу было что почитать: научно-фантастический хоррор «Сигнал из глубины», slice-of-life «Кофейня на перекрёстке» и «Ключ от чердака» — первая история с переменными и условными выборами, 4 концовки.

## Технологии

- [Vite](https://vite.dev/) + [React 19](https://react.dev/) + TypeScript (строгий режим, `tsc -b`)
- [Tailwind CSS v4](https://tailwindcss.com/) через `@tailwindcss/vite`, класс-based dark mode
- [React Flow](https://reactflow.dev/) для графа сцен в редакторе и режима карты в плеере
- [Zustand](https://github.com/pmndrs/zustand) с `persist` (localStorage) для библиотеки историй, прогресса и настроек
- [Vitest](https://vitest.dev/) + Testing Library для модульных тестов: 238 тестов — чистая логика движка (`engine/`) и поведение экранов (`screens/`) и компонентов через рендеринг и пользовательские взаимодействия (`@testing-library/user-event`)

## Архитектура

Доменная логика полностью отделена от UI и живёт в `src/engine/` как чистые иммутабельные функции — это позволяет тестировать её без рендеринга компонентов и держать React Flow исключительно слоем визуализации.

```
src/
├─ types/story.ts        # Story, StoryNode, Choice, StoryVariable — доменные типы
├─ engine/
│  ├─ id.ts               # генерация идентификаторов
│  ├─ storyOps.ts         # неизменяемые CRUD-операции над графом истории, переменными, условиями и эффектами
│  ├─ traverse.ts         # BFS-обходы: достижимость, концовки, статистика, авторасстановка
│  ├─ validate.ts         # поиск проблем истории (ошибки/предупреждения)
│  ├─ play.ts             # редьюсер прохождения истории игроком — учитывает переменные, условия и эффекты
│  ├─ storySchema.ts      # рантайм-валидация JSON при импорте файлов (с поддержкой старых сохранений без переменных)
│  ├─ flowAdapters.ts     # преобразование Story → узлы/рёбра React Flow
│  ├─ exportHtml.ts       # генерация самостоятельного HTML-файла со встроенным плеером
│  ├─ achievements.ts     # сквозные ачивки по библиотеке и прогрессу прохождений
│  ├─ librarySort.ts      # сортировка списка историй в библиотеке
│  ├─ libraryFilter.ts    # фильтр списка историй по состоянию прохождения
│  ├─ readingTime.ts      # оценка времени чтения истории по числу слов в достижимых сценах
│  ├─ templates.ts        # готовые заготовки историй (детектив, квест) для диалога создания
│  └─ findReplace.ts      # поиск и массовая замена текста по названиям сцен, тексту и вариантам выбора
├─ store/                 # Zustand-хранилища (библиотека, прогресс, настройки, UI-навигация)
├─ hooks/useDialogA11y.ts # фокус-менеджмент и закрытие по Escape для модальных диалогов
├─ components/            # переиспользуемые презентационные компоненты
├─ screens/               # Library / Editor / Player — экраны приложения
└─ data/sampleStories.ts  # встроенные демо-истории
```

Поток данных в редакторе и плеере единообразен: единственный источник истины — `Story` в Zustand-хранилище; React Flow получает узлы/рёбра, пересчитанные из него через `flowAdapters`, а любое изменение графа (перетаскивание, соединение, удаление) уходит обратно в хранилище через функции `engine/storyOps.ts`.

## Начало работы

```bash
npm install
npm run dev       # дев-сервер с HMR
npm run build     # проверка типов (tsc -b) + production-сборка
npm run test      # запуск тестов (vitest run)
npm run lint      # ESLint
```

GitHub Actions (`.github/workflows/ci.yml`) прогоняет lint, тесты и сборку на каждый push и pull request.

## Импорт и экспорт

Каждую историю можно экспортировать как отдельный JSON-файл либо выгрузить резервную копию всей библиотеки сразу. При импорте файл проходит рантайм-валидацию структуры (`engine/storySchema.ts`) — так что случайно подсунутый произвольный JSON не сломает приложение, а просто покажет понятную ошибку.

Кнопка «HTML» на карточке истории генерирует отдельный файл с тем же сюжетом и небольшим встроенным плеером на чистом JavaScript (`engine/exportHtml.ts`) — его можно отправить кому угодно, он откроется в любом браузере без интернета и без самого Plotline.
